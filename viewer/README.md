# MemForge P9 — Trace Viewer Interface

The **MemForge Trace Viewer** is a static HTML/JavaScript dashboard for replaying and analyzing memory management simulation traces generated by `memforge`. It supports both the **Contiguous Memory Subsystem** (First-Fit, Best-Fit, Worst-Fit, compaction) and the **Paging Subsystem** (FIFO, LRU, OPT, Belady's anomaly analysis) strictly complying with `docs/ARCHITECTURE.md` (ADR-004).

---

## 1. Quick Start

### Option A: Open directly in your browser
Simply double-click or open either of the following files in any modern web browser (Edge, Chrome, Firefox, Safari):
- **`viewer/index.html`**: Standard modular viewer (links `style.css` and `app.js`).
- **`viewer/standalone.html`**: Single-file bundled edition (inlined CSS & JS; 100% self-contained).

No local web server, build toolchain, or external internet connection is required.

### Option B: Using VS Code Live Server
1. Open the `memforge` repository in VS Code.
2. Right-click `viewer/index.html` and select **"Open with Live Server"**.

## 2. Supported Formats & Schema

The viewer parses and validates **JSONL** (Newline Delimited JSON) traces produced by the MemForge simulator:
- **Schema Version**: `schema: 1` (defined in `docs/ARCHITECTURE.md` Section 11).
- **Line 1**: Must be a `TraceHeader` object containing:
  ```json
  {"type":"TraceHeader","schema":1,"engine":"0.1.0","git":"...","workload":"...","policy":"...","config":{...},"trace_level":1}
  ```
- **Step Events**:
  ```json
  {"seq":13,"step":4,"type":"PlacementDecided","data":{"policy":"first-fit","requested":426,"granted":426,"hole":null,"scanned":5}}
  {"seq":14,"step":4,"type":"AllocationFailed","data":{"pid":"P4","id":"a4","requested":426,"granted":426,"cause":"FRAGMENTATION","total_free":959,"largest_hole":300}}
  ```
- **Step Snapshots**:
  - **Contiguous**:
    ```json
    {"type":"Snapshot","step":4,"contiguous":{"memory_size":1740,"blocks":[{"start":0,"size":100,"state":"free"},...],"frag":{"total_free":959,"largest_hole":300,"hole_count":5,"ext_frag":0.687174,"used":781}}}
    ```
  - **Paging**:
    ```json
    {"type":"Snapshot","step":3,"paging":{"frames":[{"frame":0,"pid":"P0","vpn":7,"referenced":true,"dirty":false},...],"page_tables":{"P0":[...]},"policy_state":{"policy":"fifo","queue":[0,1,2]}}}
    ```
- **Closing RunSummary**:
  ```json
  {"type":"RunSummary","metrics":{"alloc_requests":4,"alloc_failures":1,"failures_fragmentation":1,"ext_frag_final":0.687174}}
  ```

## 3. Playback Controls & Navigation

| Control | Action | Keyboard Shortcut |
| :--- | :--- | :--- |
| **Play / Pause** | Toggle continuous sequential playback | `Space` |
| **Previous Step** | Move backward one step | `←` or `k` |
| **Next Step** | Move forward one step | `→` or `j` |
| **Reset** | Jump to Step 0 / initial state | `Home` or `r` |
| **Next Fault** | Jump directly to next `AllocationFailed` or `PageFault` | `f` |
| **Scrubber Slider** | Drag slider to jump to any step in the trace | Mouse drag |
| **Speed Selector** | Choose speed: 0.5x (1000ms), 1.0x (500ms), 2.0x (250ms), 5.0x (100ms) | UI dropdown |

## 4. Subsystem Visualizations

### Contiguous Memory Subsystem
- **Proportional Memory Map**: Displays memory `[0, memory_size)`. Allocated blocks are color-coded by Process ID (`SYS` = slate, `P0` = cyan, `P1` = green, `P2` = purple, `P3` = rose, `P4` = amber, etc.). Free holes feature a distinct diagonal hatch pattern.
- **Minimum Block Width**: Blocks enforce an 18px minimum visible width with scrollable container so tiny blocks (e.g., 10-unit system blocks) remain visible, hoverable, and clickable.
- **Block Inspector**: Clicking any block inspects Process ID, Allocation ID, Address Range `[start, start+size)`, Size, Requested, and Internal Fragmentation.
- **Compaction Highlight**: Relocated blocks during compaction steps are highlighted with an active pulse animation.

### Paging Subsystem
- **Physical Frame Table**: Displays all physical frames with resident PID, Page identifier, Referenced (R) bit, and Dirty (D) bit. Active access highlights hits (green), faults/loads (cyan), and evictions (red).
- **Page Tables**: Process page table breakdown showing VPN, Frame mapping, and Present flags.
- **Policy State**: Shows FIFO queue (load order), LRU order, or OPT distance metrics.

### Live Metrics & Event Details
- Real-time display of **External Fragmentation**, **Memory Utilization**, **Total Free**, **Largest Hole**, or **Page Fault Rate**, **Hit Rate**, **Evictions**, and **Write-backs**.
- **Timeline Sparkline**: Visual trend of fragmentation and fault accumulation across all steps.
- **Event Explanation**: Formatted event stream with sequence numbers, event chips, and natural language explanation of policy decisions.

## 5. Viewer Step Cap & Incomplete Traces

- **5,000-Step Limit**: In accordance with `docs/ARCHITECTURE.md` Section 19, the viewer applies a strict 5,000-step display cap. If a trace exceeds 5,000 steps, the viewer loads the first 5,000 steps and displays a prominent warning banner. It **never silently displays an incomplete trace as complete**.
- **Incomplete Traces**: If a trace lacks a closing `RunSummary` record or contains missing snapshots, a notification alert informs the user that the trace is truncated while safely replaying the available steps.

## 7. Running Tests

Automated unit tests and metric validation tests run using Node.js:

```powershell
# Run the complete viewer test suite
node tests/unit/viewer/test_viewer.js

# Run the metrics and invariants calculation test suite
node tests/unit/viewer/test_metrics_calculation.js

# Or from inside the viewer/ directory:
npm test
```

### Coverage
- Valid contiguous memory traces.
- Valid paging traces.
- Malformed JSON / syntax error detection with exact line numbers.
- Missing `TraceHeader` and unsupported schema versions.
- Empty and whitespace files.
- Single-step traces.
- Missing optional fields.
- Deterministic playback boundary tests (start, end, reset, jump).
- 5,000-step viewer limit and warning flags.
- Metric formula accuracy (ext_frag, fault rates, total memory conservation).

## 8. Building the Standalone Viewer

To regenerate the self-contained single-file bundle:
```powershell
node viewer/build.js
```
This updates `viewer/standalone.html` by embedding `viewer/style.css` and `viewer/app.js` into `viewer/index.html`.
